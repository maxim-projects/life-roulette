## 1. Обзор

Пошаговая 3D-игра в стиле "русской рулетки с дробовиком" для веба. До 7 игроков на одном устройстве (hot-seat) или один игрок против бота. Вдохновлено игрой *Buckshot Roulette* Майка Клубники, с авторскими дополнениями.

**Целевая платформа:** мобильный браузер в первую очередь, работает и на десктопе.

**Деплой:** GitHub Pages, статика (без бэкенда).

## 2. Цели проекта

- Семейный проект: папа + сын учатся вместе делать игру
- Поэтапная разработка: MVP (оффлайн) → онлайн позже
- 3D-графика в стиле PSX (low-poly + low-res textures + атмосферное освещение)
- Игра должна быть весёлой и реиграбельной
- Чистая архитектура: отделение логики от рендера, готовность к расширению

## 3. Не-цели для MVP (Phase 1)

- ❌ Онлайн-мультиплеер (Phase 3)
- ❌ Классы персонажей (Phase 1.5)
- ❌ Спецпатроны и кастомизация магазина (Phase 1.5)
- ❌ Звуковой дизайн (Phase 1.5)
- ❌ PSX-кастомшейдер с vertex jitter / affine UV (Phase 2 как опция)
- ❌ Реальные деньги / донаты с платёжкой
- ❌ Альтернативные камеры (DuelScene = Phase 1.5)

## 4. Глоссарий

| Термин | Что это |
|--------|---------|
| **Револьвер** | Оружие на столе. (Не "пистолет" / не "дробовик" — определились на одном термине) |
| **Обойма** | Барабан револьвера на 6 патронов. После исчерпания — перезарядка |
| **Патрон** | Единица в обойме. Тип: `live` (боевой) или `blank` (холостой) |
| **Жизнь** | Единица здоровья игрока, 0..4 |
| **Раунд** | Цикл "рулетка → зарядка → ходы пока обойма не пуста" |
| **Игра** | Последовательность раундов до победы одного игрока |
| **Сессия** | Все игры на одном устройстве с момента открытия страницы |

## 5. Игровой процесс

### 5.1. Стартовое состояние игры

- Игрок выбирает режим: **vs компьютер** (1 человек + 1 бот) или **hot-seat** (2-7 человек)
- В hot-seat: каждый человек выбирает свой **профиль** (имя). Если профиля нет — создаётся новый. Профили хранятся локально (см. раздел 7.2)
- Каждый игрок начинает игру с **4 жизнями**, **1 шоколадкой**, **1 лупой** (плюс предметы из своего профильного инвентаря, см. раздел 7)

### 5.2. Структура раунда

```
1. РУЛЕТКА
   └→ револьвер крутится, указывает на одного из живых игроков
   └→ этот игрок ходит первым в раунде
2. ЗАРЯДКА
   └→ выбирается случайный liveCount ∈ [1..5]
   └→ blankCount = 6 - liveCount
   └→ 6 патронов перемешиваются (Fisher–Yates) и помещаются в обойму
   └→ игрокам показывается: "В обойме N боевых и M холостых"
3. ХОДЫ
   └→ игроки ходят по очереди, начиная с того, на кого указала рулетка
   └→ порядок: по часовой стрелке от первого, пропуская выбывших
   └→ цикл: ход → выстрел → возможна смена хода → следующий игрок
   └→ продолжается пока обойма не пуста ИЛИ остался один живой
4. ЕСЛИ ОБОЙМА ПУСТА И ИГРА ИДЁТ → переход на шаг 1
5. ЕСЛИ ОДИН ЖИВОЙ → ПОБЕДА (см. 5.6)
```

### 5.3. Структура одного хода

Ход — это формальный конечный автомат:

```
[Начало хода игрока N]
  │
  ▼
[item-phase]  ◄────────────────────────┐
  │                                    │
  ├─ использовать лупу (≤1 раз/ход)   │ (по желанию)
  ├─ использовать шоколадку (≤1 раз)  │
  │                                    │
  ▼                                    │
[shot-phase]  (обязательно)
  │
  ├─ выбрать цель: себя | кого-то из живых
  ├─ выстрел → выпадает следующий патрон обоймы
  ├─ резолв (см. 5.4)
  │
  ▼
[turn-end]
  │
  ├─ if обойма пуста: следующий шаг = "новая рулетка + зарядка"
  ├─ else if extra-turn активен и cap не достигнут: тот же игрок ходит снова
  └─ else: ход → следующий живой игрок (по часовой)
```

**Правила фазы предметов:**
- Каждый предмет можно использовать **максимум 1 раз за свой ход**
- Использование предмета **не заканчивает ход** (потом обязателен выстрел)
- Если на старте хода обойма уже пуста → форсированно "конец хода" → "новая рулетка"

**Правило выстрела:** ход обязан завершиться выстрелом (если обойма не пуста). Нельзя "пропустить" выстрел.

### 5.4. Резолв выстрела

| Действие | Холостой патрон | Боевой патрон |
|----------|-----------------|---------------|
| Стрелять в себя | "Extra turn" granted (см. 5.5) | -1 жизнь себе, ход переходит |
| Стрелять в другого живого | Ничего, ход переходит | Цель -1 жизнь, ход переходит |

После выстрела:
- Если жизни цели стали 0 → цель помечается выбывшей (`eliminated`), её нельзя больше выбирать целью, она пропускается в порядке ходов
- Если осталось 1 живых → конец игры (победа)

### 5.5. Extra turn (защита от абуза)

После выстрела в себя холостым — игроку даётся "extra turn": он ходит ещё раз с той же обоймой.

**Cap**: не более **1 extra turn в одном раунде** (одна обойма) на одного игрока.

Реализация: счётчик `extraTurnsUsedThisChamber: Map<playerId, number>`, сбрасывается при перезарядке.

Эффект: игрок может один раз "обнулить" холостой ход и получить второй шанс. Не может монополизировать обойму через repeated self-shots.

### 5.6. Победа

- Когда остался **один живой игрок** — он победитель
- Победителю: экран "Ты победил!" + анимация кубка + **+200 валюты**
- Все остальные участники игры (включая бота): **+50 валюты** за участие
- Возможность вернуться в меню или начать новую игру

### 5.7. Бот (vs AI)

Бот — это игрок управляемый детерминированным алгоритмом. Используется только в режиме vs AI.

**Алгоритм** (минимальная heuristic для MVP):

```
INPUT: PlayerView (что бот знает)
OUTPUT: Action (выстрел или использование предмета)

1. Если есть лупа в инвентаре И ещё не использовал её этот ход:
   → используй лупу

2. Если знаю следующий патрон (через лупу):
   ├─ Если live:
   │   ├─ Если у меня ≤1 жизнь и есть шоколадка: используй шоколадку (отлинуть)
   │   └─ Стреляй в самого слабого живого противника
   └─ Если blank:
       ├─ Если cap на extra turn НЕ достигнут: стреляй в себя (получи extra turn)
       └─ Иначе: стреляй в самого слабого живого противника

3. Если не знаю следующий патрон:
   ├─ Если в обойме ≥3 живых патронов: стреляй в самого слабого противника (риск стоит того)
   ├─ Если в обойме ≥2 холостых: стреляй в себя (50/50, ради extra turn)
   └─ Иначе: стреляй в самого слабого противника
```

Алгоритм детерминированный (с seeded RNG для tie-breaking). Один уровень сложности в MVP.

## 6. Магазин

### 6.1. Когда открывается
- Из главного меню (перед началом игры)
- После окончания игры (победа/поражение/выход)

### 6.2. Что продаётся в MVP

| Товар | Цена (валюта) | Эффект при использовании |
|-------|---------------|--------------------------|
| Шоколадка | 50 | +1 жизнь (макс 4); 1 использование за ход |
| Лупа | 50 | Раскрыть следующий патрон в обойме; 1 использование за ход |

**Холостой патрон как предмет — удалён** (по решению дизайнера: купить нельзя, его не существует как предмета).

### 6.3. Валюта

- Зарабатывается:
  - **+200** за победу в игре
  - **+50** за участие в игре (выбывшим тоже)
  - Бот **не** получает валюту (накапливается только у людей-игроков)
- Сохраняется в профиле игрока (см. 7.2), не на устройстве в целом

### 6.4. Инвентарь и лимиты

- Каждый профиль имеет свой инвентарь: `Record<ItemId, number>` (число каждого вида предмета)
- На старте каждой игры:
  - У каждого игрока: 1 шоколадка + 1 лупа (стартовый набор)
  - **Плюс** что докупил из своего профильного инвентаря
- Лимит количества **5 предметов каждого вида** в инвентаре профиля
- Бот: 1 шоколадка + 1 лупа (стартовый набор только, без инвентаря)

## 7. Профили игроков

### 7.1. Назначение

Hot-seat предполагает несколько разных людей за одним устройством. У каждого должен быть свой кошелёк и инвентарь. Иначе все игроки будут "тратить общий" кошелёк.

### 7.2. Структура профиля

```typescript
interface PlayerProfile {
  id: string;       // UUID
  name: string;     // отображаемое имя
  currency: number; // валюта
  inventory: Record<ItemId, number>;
  createdAt: number;
  lastUsed: number;
}
```

Хранятся в `localStorage` под ключом `life-roulette:profiles` как JSON-массив.

### 7.3. UI выбора профиля

При начале новой игры в hot-seat-режиме каждому участнику показывается:
- Список существующих профилей (карточки с именем + валютой)
- Кнопка "Создать новый профиль"
- Кнопка "Гость" (одноразовый профиль, не сохраняется)

В режиме vs AI: профиль один (главный игрок), бот — без профиля.

## 8. Архитектура

### 8.1. Принципы

1. **Engine не знает про DOM/Three.js.** GameEngine — чистая TypeScript-функция от состояния и действия к новому состоянию + событиям.
2. **Sceneы — плагины.** Интерфейс `Scene3D` поддерживает несколько реализаций (TableScene в MVP, DuelScene позже).
3. **HUD отдельно от 3D.** UI меню/HUD — vanilla DOM. Не зависит от Three.js.
4. **Persistence — отдельный модуль** в `src/persistence/`. Магазин и профили обращаются туда.
5. **Бот не импортирует engine.** Бот — чистая функция `(view, rng) → Action`.
6. **Seeded RNG.** Все случайности (рулетка, шуффл обоймы, тай-брейкеры в боте) проходят через `rng()` функцию с seed. Тесты используют фиксированный seed.
7. **Action log.** Engine ведёт журнал всех Action'ов. Это база для Phase 3 (онлайн).

### 8.2. Слои

```
┌────────────────────────────────────────┐
│  UI (DOM, CSS)                         │  ← меню, шоп, HUD, профили
├────────────────────────────────────────┤
│  Game Controller                       │  ← оркестрация: engine + scene + HUD + ввод + privacy
├────────────────────────────────────────┤
│  Game Engine (чистая логика)           │  ← state, action, events, action log
│  ┌─────────────┐  ┌──────────────────┐│
│  │ Bot (pure)  │  │ Chamber (pure)   ││
│  └─────────────┘  └──────────────────┘│
├────────────────────────────────────────┤
│  Scene3D Plugin (Three.js)             │  ← рендер сцены, анимации, target picking
├────────────────────────────────────────┤
│  Persistence (localStorage / session)  │  ← профили, валюта, инвентарь, mid-game state
└────────────────────────────────────────┘
```

### 8.3. Главные сущности

```typescript
type ItemId = 'chocolate' | 'magnifier';
type Bullet = 'live' | 'blank';

interface Player {
  id: string;
  name: string;
  profileId: string | null;  // null для бота и гостей
  lives: number;             // 0..4
  inventory: Record<ItemId, number>;
  isBot: boolean;
  eliminated: boolean;
}

interface Chamber {
  bullets: Bullet[];   // ≤6 в обойме (выстреленные удалены с фронта)
  liveCount: number;   // публично известно: сколько боевых ОСТАЛОСЬ
  blankCount: number;  // публично известно: сколько холостых ОСТАЛОСЬ
}

type GamePhase =
  | 'menu'
  | 'profile-select'
  | 'roulette'        // анимация рулетки
  | 'loading'         // зарядка обоймы (короткая анимация)
  | 'turn-item'       // фаза предметов в ходе
  | 'turn-shot'       // фаза выстрела
  | 'turn-resolve'    // показ результата
  | 'pass-device'     // hot-seat: "передай телефон [Имя]"
  | 'paused'          // visibility-hidden или явная пауза
  | 'between-rounds'  // короткая пауза между обоймами
  | 'game-over'
  | 'shop';

interface GameState {
  players: Player[];
  currentPlayerIndex: number;
  chamber: Chamber;
  phase: GamePhase;
  rngSeed: number;
  rngState: number;     // current RNG state (mutable)
  extraTurnsUsedThisChamber: Record<string, number>;
  itemsUsedThisTurn: Record<ItemId, boolean>;
  winnerId: string | null;
  actionLog: Action[];
}

type Action =
  | { type: 'spin-roulette' }
  | { type: 'load-chamber' }
  | { type: 'use-item'; itemId: ItemId }
  | { type: 'shoot'; targetId: string };

type GameEvent =
  | { type: 'roulette-spun'; firstPlayerId: string }
  | { type: 'chamber-loaded'; liveCount: number; blankCount: number }
  | { type: 'item-used'; playerId: string; itemId: ItemId }
  | { type: 'shot-fired'; shooterId: string; targetId: string; bullet: Bullet }
  | { type: 'lives-changed'; playerId: string; newLives: number }
  | { type: 'extra-turn-granted'; playerId: string }
  | { type: 'extra-turn-cap-hit'; playerId: string }
  | { type: 'player-eliminated'; playerId: string }
  | { type: 'turn-changed'; nextPlayerId: string }
  | { type: 'chamber-empty' }
  | { type: 'game-over'; winnerId: string };
```

### 8.4. Privacy: peek-state в Controller

`GameState` информационно-публичен (всё что в нём — известно всем). Лупа раскрывает приватную информацию только текущему игроку — она НЕ хранится в GameState.

```typescript
// В Controller, не в Engine:
class TurnPrivateState {
  peekedNextBullet: Bullet | null = null;
  // показать только текущему игроку через приватный экран
}
```

Это решает: в hot-seat другой игрок не может прочитать peek; в Phase 3 онлайна сервер не должен скрывать peek от других — оно вообще не было в общем состоянии.

### 8.5. PlayerView (для бота и для онлайна)

```typescript
function getPlayerView(state: GameState, playerId: string): PlayerView {
  return {
    selfPlayer: state.players.find(p => p.id === playerId)!,
    otherPlayers: state.players
      .filter(p => p.id !== playerId)
      .map(p => ({ id: p.id, name: p.name, lives: p.lives, eliminated: p.eliminated })),
    chamberLive: state.chamber.liveCount,
    chamberBlank: state.chamber.blankCount,
    currentPlayerId: state.players[state.currentPlayerIndex].id,
    phase: state.phase,
    // peekedNextBullet НЕ ВКЛЮЧЕН — это privacy state в Controller
  };
}
```

Бот получает `PlayerView` + opportunistic `peekedNextBullet` (если его клиент использовал лупу) — но всё это локально, не в GameState.

Реализации:
- `TableScene` (MVP) — вид сверху на круглый стол, фигурки игроков по кругу. Поддерживает 2-7 игроков. Target picking через UI-кнопки (выбор цели по имени), не через клик на 3D-фигуру.
- `DuelScene` (Phase 1.5) — камера сбоку, 1v1 вид. Target picking через клик на оппонента в сцене.

## 10. UI/UX

### 10.1. Главное меню
- Кнопка "Играть" → выбор режима
- Кнопка "Магазин"
- Кнопка "Профили"
- Текущая валюта (если выбран профиль)

### 10.2. Режим / профиль
- Выбор режима: vs AI / hot-seat
- Если hot-seat: выбор количества (2-7), для каждого — выбор/создание профиля или "гость"
- Если vs AI: выбор главного профиля

### 10.3. Игровой экран
- Сверху: список игроков с жизнями + индикатор текущего хода
- Центр: 3D-сцена (TableScene)
- Внизу: ActionMenu (стрелять/предмет), счётчик патронов

### 10.4. Hot-seat: "передай телефон"
- Между ходами: fullscreen экран "Передай [Имя]" + кнопка "Готов"
- Скрывает все приватные данные (peek, инвентарь предыдущего игрока)

### 10.5. Приватный peek-экран
- При использовании лупы: текущий игрок видит fullscreen "Только для [Имя]" → tap → "Следующий патрон: 🔴 БОЕВОЙ" / "🟢 ХОЛОСТОЙ" → кнопка "Скрыть и вернуться"
- При hide → возврат в обычный игровой экран без раскрытия

### 10.6. Подтверждения
- Стрельба: одноклик на цель → confirm-overlay "Стрелять в [Имя]?" → "Стрелять / Отмена"
- Покупка: при цене >=100 — confirm "Купить [Товар] за [Цена]?"

### 10.7. Loading screen
- Прогресс-бар при загрузке 3D-ассетов на старте
- Таймаут 30 сек → ошибка "Не удалось загрузить, обновить?"

### 10.8. Pause / visibility
- При `visibilitychange` (свернули вкладку): сохранение mid-game state в sessionStorage, фаза → `paused`
- При возврате: восстановление, фаза → предыдущая

### 10.9. Адаптивность
- Mobile-first: portrait mode, hit targets ≥44px
- Поддержка touch + mouse одновременно

## 11. Стиль графики (упрощённо)

В MVP без custom shader. Достигается:
- Низкополигональные модели (1000-3000 polys main object)
- Текстуры низкого разрешения (128-256px)
- Атмосферное освещение: тёплая лампа сверху, тёмные углы
- Лёгкая виньетка на постпроцессе (built-in Three.js)

PSX-эффекты (vertex jitter, affine UV, dithering) — Phase 2, через готовый шейдер из npm (типа `three-psx-shader` или подобного), не пишем с нуля.

3D-модели:
- Только **CC0** или с **явной коммерческой лицензией**
- Источники: Poly Haven, Kenney.nl, проверенные пакеты на Sketchfab
- Все источники в `CREDITS.md`

## 16. Риски

- **3D-разработка с нуля** для семейного проекта — амбициозно. План Б: упростить до 2D с pixel-art.
- **Hot-seat UX на телефоне** для 7 игроков — длительность игры. Опция "сократить жизни до 2-3 для 6+ игроков" — отложена, проверим в playtest.
- **Тематика рулетки** — для широкой аудитории может быть проблема. Для семейного использования — ок. Если делаем "публичную" — рассмотреть soft reskin.
- **Лицензии 3D-ассетов** — обязательно проверять каждый файл. Один лицензионный конфликт может закрыть публичный деплой.
