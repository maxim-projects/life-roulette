## 1. Обзор

Пошаговая 3D-игра в стиле "русской рулетки с дробовиком" для веба. До 7 игроков на одном устройстве (hot-seat) или один игрок против бота. Вдохновлено игрой *Buckshot Roulette* Майка Клубники, с авторскими дополнениями: магазин с валютой, классы персонажей (отложено), мульти-плеер.

**Целевая платформа:** мобильный браузер в первую очередь, работает и на десктопе.

**Деплой:** GitHub Pages, статика (без бэкенда).

## 2. Цели проекта

- Семейный проект: папа + сын учатся вместе делать игру
- Поэтапная разработка: MVP (оффлайн) → онлайн позже
- 3D-графика в стиле PSX (стилизованная "ретро" 3D, как Buckshot Roulette)
- Игра должна быть весёлой и реиграбельной
- Чистая архитектура: отделение логики от рендера, готовность к расширению

## 3. Не-цели для MVP (Phase 1)

- ❌ Онлайн-мультиплеер (Phase 3, отдельный спек)
- ❌ Классы персонажей (Phase 1.5, см. раздел 11)
- ❌ Спецпатроны (Phase 1.5)
- ❌ Звуковой дизайн (Phase 1.5 — добавим, когда геймплей стабилен)
- ❌ Достижения, таблицы лидеров, статистика
- ❌ Реальные деньги / донаты с платёжкой (см. раздел 11)

## 4. Игровой процесс — правила

### 4.1. Стартовое состояние
- Игрок выбирает режим: **vs компьютер** или **hot-seat 2-7 игроков**
- В hot-seat: каждый вводит своё имя
- Каждый игрок начинает с **4 жизнями**, **1 шоколадкой**, **1 лупой**
- (Если у игрока в инвентаре есть купленные предметы — они тоже добавляются к стартовому набору)

### 4.2. Структура раунда (loop)
1. **Рулетка**: пистолет крутится на столе (анимация). Куда указал — тот ходит **первым** в этом раунде.
2. **Зарядка**: ведущий заряжает обойму **6 патронами** в случайном порядке (микс боевых и холостых). Игроки видят **сколько каких всего**, но не порядок.
3. **Ходы**: игроки ходят по кругу (по часовой стрелке от первого), пока обойма не пуста. На своём ходу игрок выбирает одно действие:
   - 🎯 Стрелять в себя
   - 🎯 Стрелять в другого игрока (выбор цели)
   - 🍫 Использовать шоколадку (+1 жизнь, не больше 4)
   - 🔍 Использовать лупу (показать какой следующий патрон)
   - 🔫 Использовать холостой патрон (текущий патрон в стволе превращается в холостой)
4. **Резолв выстрела**: см. таблицу 4.3
5. **Конец обоймы**: когда все 6 патронов потрачены → возврат к шагу 1 (новая рулетка → новая зарядка)
6. **Конец игры**: остался один живой игрок (3.x — см. 4.4)

### 4.3. Таблица последствий выстрела

| Действие | Холостой патрон | Боевой патрон |
|----------|-----------------|---------------|
| Стрелять в себя | Игрок ходит ещё раз | Игрок -1 жизнь, ход переходит |
| Стрелять в другого | Ничего, ход переходит | Цель -1 жизнь, ход переходит |

### 4.4. Выбывание и победа
- Игрок с **0 жизней** выбывает: сидит и наблюдает, не может действовать, его нельзя выбрать целью
- При смене первого хода (рулетка) выбывшие пропускаются
- Когда остался **один живой игрок** — он победитель
- Победителю: экран "Ты победил!" + анимация кубка + **+200 валюты** в кошелёк

### 4.5. Бот (vs компьютер)
- В режиме vs AI один из игроков — бот, который принимает решения за себя
- Бот учитывает: текущее количество боевых/холостых, использовал ли лупу, своё здоровье, здоровье цели
- Сложность бота — одна для MVP (sane defaults). Усложнение/режимы сложности — будущее улучшение.

## 5. Магазин

### 5.1. Когда открывается
- Из главного меню (перед началом игры)
- После окончания игры (победа/поражение)

### 5.2. Что продаётся в MVP

| Товар | Цена (валюта) | Эффект при использовании в игре |
|-------|---------------|----------------------------------|
| Шоколадка | 50 | +1 жизнь (не больше 4) |
| Лупа | 50 | Показать какой следующий патрон в обойме |
| Холостой патрон | 500 | Текущий патрон в стволе превращается в холостой |

Цены ориентированы на пометки юного разработчика (см. фото шопа от 2026-04-30).

Купленные предметы добавляются **сверх стартового набора** (1 шоколадка + 1 лупа по умолчанию у каждого игрока в начале игры).

### 5.3. Валюта
- Зарабатывается победами в игре (+200 за выигранную игру)
- Сохраняется в `localStorage` браузера (привязана к устройству)
- В MVP **нет реальных денег** и нет онлайн-синхронизации

### 5.4. Инвентарь
- Между играми инвентарь сохраняется в `localStorage`
- В начале каждой игры: к сохранённому инвентарю добавляется стартовый набор (1 шоколадка + 1 лупа)
- Лимит на одновременное количество одинаковых предметов в инвентаре — **5 штук каждого вида** (мягкий лимит, чтобы не было "100 шоколадок")

## 6. Архитектура

### 6.1. Принципы
- **Чистая логика игры** (без рендера) — `GameEngine` тестируется без браузера
- **Сцена как плагин** — интерфейс `Scene3D`, реализация `DuelScene` (для камеры A), позже добавим `RoundTableScene` (для камеры B)
- **HUD отдельно от 3D** — DOM-based UI поверх 3D-канвы
- **Контроллер режима** — оркестрирует engine + scene + HUD + ввод. Сейчас `OfflineGameController`, в будущем добавится `OnlineGameController`

### 6.2. Слои

```
┌──────────────────────────────────────┐
│  UI (HTML/CSS, DOM)                  │  ← меню, имена, шоп, HUD во время игры
├──────────────────────────────────────┤
│  Game Controllers (Offline / Online) │  ← склейка слоёв
├──────────────────────────────────────┤
│  Game Engine (чистая логика, TS)     │  ← state, actions, events. Без рендера.
├──────────────────────────────────────┤
│  Scene3D (Three.js)                  │  ← рендер сцены, анимации
├──────────────────────────────────────┤
│  Persistence (localStorage)          │  ← валюта, инвентарь
└──────────────────────────────────────┘
```

### 6.3. Главные сущности

```typescript
type ItemId = 'chocolate' | 'magnifier' | 'blank-cartridge';
type Bullet = 'live' | 'blank';

interface Player {
  id: string;
  name: string;
  lives: number;          // 0..4
  inventory: ItemId[];
  isBot: boolean;
  eliminated: boolean;
}

interface Chamber {
  bullets: Bullet[];      // от 6 до 0
  // Игроки видят counts, но порядок скрыт
}

interface GameState {
  players: Player[];
  currentPlayerIndex: number;
  chamber: Chamber;
  phase: 'menu' | 'roulette' | 'loading' | 'turn' | 'between-rounds' | 'game-over';
  winnerId: string | null;
  peekedNextBullet: Bullet | null;  // от лупы, видно только текущему игроку
}

type Action =
  | { type: 'shoot'; targetId: string }   // self или другой
  | { type: 'use-item'; itemId: ItemId };

type Event =
  | { type: 'roulette-spun'; firstPlayerId: string }
  | { type: 'chamber-loaded'; liveCount: number; blankCount: number }
  | { type: 'shot-fired'; shooterId: string; targetId: string; bullet: Bullet }
  | { type: 'lives-changed'; playerId: string; newLives: number }
  | { type: 'player-eliminated'; playerId: string }
  | { type: 'item-used'; playerId: string; itemId: ItemId }
  | { type: 'turn-changed'; nextPlayerId: string }
  | { type: 'chamber-empty' }
  | { type: 'game-over'; winnerId: string };
```

### 6.4. Интерфейс сцены (для расширяемости A → B)

## 7. Технологический стек

- **TypeScript** — статическая типизация, ловит ошибки
- **Three.js** — 3D-рендер
- **Vite** — dev-сервер и сборка (быстрая)
- **vitest** — юнит-тесты для логики
- **Playwright** — e2e тесты (опционально, на этапе стабилизации)
- **GitHub Actions** — auto-deploy

Менеджер пакетов — `pnpm` (быстрый и компактный).

Для меню/HUD используем **vanilla DOM + CSS** (без React/Vue) — меньше зависимостей, проще на старте, и для размера проекта избыточно.

## 8. UI/UX

### 8.1. Главное меню
- Кнопка "Играть"
  - Выбор режима: vs компьютер / hot-seat
  - Если hot-seat — выбор количества игроков (2-7), ввод имён
- Кнопка "Магазин"
- Отображение текущей валюты

### 8.2. Игровой экран (3D + HUD)
- 3D-сцена занимает основную часть экрана
- HUD сверху: список игроков с жизнями, текущий игрок выделен
- HUD снизу/сбоку: инвентарь текущего игрока, счётчик патронов в обойме
- Hot-seat passing: между ходами экран "Передай телефон [Имя]" с кнопкой "Готов"

### 8.3. Адаптивность
- Mobile-first: дизайн под телефон в портретной ориентации
- Кликабельные элементы достаточно крупные для пальца
- Поддержка touch + mouse одновременно

## 9. Стиль графики (PSX-look)

Достигается через:
- Низкополигональные модели (1000-3000 polys на главные объекты)
- Текстуры низкого разрешения (128x128, 256x256), с pixel-art ощущением
- Custom shader с эффектами:
  - Vertex jitter (округление координат вершин до пиксельной сетки)
  - Affine texture mapping (характерные искажения текстур PSX)
  - Лёгкий dithering, виньетка
- Атмосферное освещение: тёплая лампа сверху, тёмные углы

3D-модели: бесплатные с Sketchfab (CC лицензия), Poly Haven, или сгенерированные/собранные простыми примитивами.

**Атмосфера сцены** (тёмный бар vs другая обстановка) — решим во время разработки, не блокирующее решение для дизайна.

## 12. MVP — критерии готовности

Игра считается готовой к Phase 1 релизу когда:

- [ ] Можно начать новую игру (vs AI или hot-seat 2-7)
- [ ] Полный игровой цикл проходится без багов: рулетка → зарядка → ходы → перезарядка → победа
- [ ] Все 3 предмета (шоколадка, лупа, холостой патрон) работают как описано
- [ ] Магазин позволяет купить предметы за заработанную валюту
- [ ] Валюта сохраняется между сессиями браузера
- [ ] Игра работает на телефоне 3-летней давности с приличным fps (≥30)
- [ ] Анимация рулетки и пистолета визуально работает
- [ ] Покрытие тестами: вся игровая логика (engine, bot, chamber) — юнит-тесты
- [ ] Деплой на GitHub Pages автоматически

## 13. Открытые вопросы (не блокируют дизайн, решим во время разработки)

- Конкретная атмосфера 3D-сцены (тёмный бар как в Buckshot или нейтральная обстановка)

- Источники 3D-моделей (бесплатные / купленные / собственные)
- Лимиты инвентаря (сколько шоколадок можно нести и т.п.)
- Точные правила пары мест в классах (когда дойдём до Phase 1.5)
- "Два уровня игрока" — что юный разработчик имел в виду

## 14. Риски

- **3D-разработка с нуля** для семейного проекта — амбициозно. Если столкнёмся со сложностями — есть план Б: упростить до 2D или low-poly cartoon.
- **Hot-seat UX на телефоне** для 7 игроков — требует тщательного тестирования "передачи телефона".
- **Тематика рулетки** — для широкой аудитории может быть проблема (App Store, реклама). Для семейного использования — ок. Если делаем "публичную" игру — можем рассмотреть мягкий рескин (например, лопнувший шарик вместо пули).
