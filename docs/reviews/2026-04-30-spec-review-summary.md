## TL;DR

**Вердикт всех трёх: spec нуждается в ревизии до начала кодинга.**

Найдено ~30 замечаний. Ничего катастрофического — всё исправимо в spec v2. Большинство критических находок попало в "слепые зоны" из-за того что я (Claude) интерпретировал двусмысленные части надиктовки в свою сторону вместо того чтобы добиться однозначности от дизайнера.

## CRITICAL (must-fix перед реализацией)

### 1. Семантика предмета "холостой патрон" не определена
**Найдено:** game-design + codex
**Проблема:** "Текущий патрон в стволе превращается в холостой" — что такое "текущий" если порядок патронов скрыт, а выстрел — отдельное действие? Что если этот патрон уже был холостым? Что показывает лупа после применения предмета?
**Фикс:** Чёткий вариант: "превращает следующий боевой в обойме в холостой; если все холостые — без эффекта; лимит 1 раз на обойму". И обновляет результат лупы, если использовалась.

### 2. Семантика лупы не определена
**Найдено:** game-design + codex (косвенно)
**Проблема:** "Показать какой следующий патрон" — расходуется ли при использовании? Знание сохраняется до выстрела или дольше? Что показывается после смены состояния обоймы (например после холостого предмета)?
**Фикс:** "Расходуется при использовании; раскрывает следующий патрон в обойме; знание остаётся пока патрон не выстрелен или не изменён предметом".

### 3. Структура хода не формализована
**Найдено:** game-design + codex
**Проблема:** "Использовать предмет" указано как **действие хода**, но логически некоторые предметы (лупа, холостой патрон) хочется применять **перед выстрелом в тот же ход**. Сейчас неясно: ход = 1 действие? Или 0–N предметов + 1 выстрел?
**Фикс:** Чёткий FSM хода: `1) (опционально) 0..N использований предметов → 2) выстрел (обязателен) → 3) ход переходит`. Лимит 3 предмета на ход во избежание абуза.

### 4. `peekedNextBullet` нарушает приватность и блокирует онлайн-future
**Найдено:** game-design + architecture + codex
**Проблема:** Поле в общем `GameState`, видно всем. В hot-seat — следующий игрок может прочитать. В онлайне — сервер не сможет скрыть от других клиентов.
**Фикс:** Перенести peek-state в Controller (приватно для текущего игрока), либо сделать `Record<playerId, Bullet | null>` с серверной фильтрацией позже.

### 5. Degenerate strategy: self-shoot loop ломает игру с 7 игроками
**Найдено:** game-design (КРИТИЧНО, уникальная находка)
**Проблема:** В оригинальном Buckshot правило "холостой в себя = ходишь снова" балансит дуэль. С 7 игроками: лупа → если холостой → стреляешь в себя → ходишь снова → опять лупа → если холостой → опять. Активный игрок монополизирует обойму, потом стреляет боевым в самого слабого. Превращает игру в детерминированную казнь.
**Фикс:** Один из:
- (A) кап на 1 self-shot подряд за обойму
- (B) убрать "extra turn on blank self" для >2 игроков, заменить наградой (+1 предмет)
- (C) шанс что свой выстрел в себя промахнётся

### 6. Распределение патронов в обойме не задано
**Найдено:** codex (уникальная)
**Проблема:** "6 патронов случайно" — но сколько боевых vs холостых? Без этого нельзя балансить, тестировать, обучать бота, гарантировать что обойма не вся холостая или вся боевая.
**Фикс:** Зафиксировать: `liveCount ∈ [2..4]`, `blank = 6-live`. Гарантия "минимум 1 каждого". RNG через seed для тестов.

### 7. Магазин + hot-seat + localStorage = дублирование инвентаря
**Найдено:** codex (уникальная)
**Проблема:** Inventory в `localStorage` привязан к устройству. В hot-seat все игроки на одном устройстве. Каждый получает копию того же инвентаря? Все стартуют с одинаковыми предметами?
**Фикс:** Один из:
- (A) В MVP магазин работает только в режиме vs AI (1 игрок = 1 устройство = 1 кошелёк)
- (B) Профили игроков с локальным сохранением `Map<playerName, Inventory>`
- (C) Между раундами случайный дроп предметов на стол (без shop-привязки к устройству)

### 8. Hot-seat 7 игроков × DuelScene = противоречие в MVP
**Найдено:** codex (уникальная)
**Проблема:** MVP заявлен с 2-7 hot-seat, но 3D-сцена `DuelScene` рассчитана на 1v1. Как будут видны 5 неучаствующих игроков?
**Фикс:** Один из:
- (A) Ограничить MVP до 2-4 игроков (расширение в Phase 1.5)
- (B) В DuelScene показывать только текущую "пару", остальные — иконки в HUD сверху
- (C) Простой "table" view для 3+ игроков (без 3D-моделей фигурок) — компромисс

### 9. Стартовые предметы у каждого игрока убивают напряжение
**Найдено:** codex (уникальная, тонкая)
**Проблема:** "1 шоколадка + 1 лупа у каждого" + 4 жизни = много буфера, медленно ускорение. С 7 игроками может быть очень долго.
**Фикс:** Один из:
- (A) Убрать стартовые, давать только из дропа/шопа
- (B) Один случайный предмет на старте (либо лупа, либо шоколадка, не оба)
- (C) Менее жизней при больше игроков: 4 для 2-3, 3 для 4-5, 2 для 6-7

## IMPORTANT (should-fix)

### 10. "Ход переходит" — к кому? Неясно
**Найдено:** codex
**Фикс:** "К следующему живому игроку по часовой стрелке от стрелявшего". Функция `nextAliveIndex(fromIndex)` в engine.

### 11. Конец обоймы при ≥2 живых, но все патроны кончились без передачи хода — undefined
**Найдено:** game-design
**Проблема:** Что если последний патрон холостой и игрок выстрелил в себя — он "ходит ещё раз", но обойма пуста?
**Фикс:** "Если обойма пуста после выстрела → форсированно фаза `loading` → новая рулетка → новая обойма".

### 12. Phase enum не покрывает hot-seat "передай телефон"
**Найдено:** architecture
**Фикс:** Добавить фазу `pass-device` (между ходами в hot-seat) и `paused` (для visibility-change на мобиле).

### 13. Visibility/Tab-switch на мобильном не обрабатывается
**Найдено:** architecture
**Фикс:** Listen `visibilitychange`, сохранять mid-game state в `sessionStorage`, восстанавливать.

### 14. Бот описан hand-wavy
**Найдено:** game-design + architecture + codex
**Фикс:** Конкретный детерминированный heuristic (с seed). Как минимум:
- Если знаю патрон (через лупу) и боевой → стреляю в самого слабого
- Если холостой → стреляю в себя для extra turn
- Шоколадку юзаю при ≤2 жизни и нет явного килла
- Лупу юзаю если ещё не знаю и патронов в обойме ≥3

### 15. Онлайн-readiness не подтверждена
**Найдено:** architecture + codex
**Проблема:** Спек заявил "архитектура поддерживает онлайн без переписывания", но:
- Бот сейчас клиент-сайд → для онлайна нужен сервер-сайд
- Peek state не приватизирован
- Нет seeded RNG → нельзя восстановить state
- Нет journal of actions → нельзя пересинхронизировать
**Фикс:** Добавить в engine: seed RNG, action log (массив всех Action), функция `getPlayerView(state, playerId)` для приватной проекции. Бот должен зависеть только от `Readonly<PlayerView>`.

### 16. Bot ↔ Engine — риск циклической зависимости
**Найдено:** architecture
**Фикс:** Bot — чистая функция `(view, rng) → Action`. Engine не импортирует bot. Controller вызывает bot и передаёт action в engine.

### 17. Награда "только победителю +200" → гринд
**Найдено:** codex
**Фикс:** +50 за участие, +200 победителю. Или "+50 за каждый успешный выстрел в живого" + бонус за победу.

### 18. Лицензии 3D-ассетов для публичного GH Pages
**Найдено:** codex
**Фикс:** Правило "только CC0 или явно разрешено для коммерческого использования". `CREDITS.md` со списком источников.

### 19. PSX shader сложен для семейной разработки
**Найдено:** architecture + codex
**Фикс:** В MVP без custom shader (просто low-poly + low-res textures + dark lighting). PSX-эффекты как stretch goal с готовым шейдером из npm.

### 20. UI-фазы смешаны с игровой логикой в `phase` enum
**Найдено:** codex
**Фикс:** В engine только game-фазы (`turn`, `chamber-empty`, `game-over`). Анимации (`roulette-spin`, `loading`) — в Controller, отдельный animation state.

### 21. Лупа в hot-seat легко "подсмотреть"
**Найдено:** codex (уникальная)
**Фикс:** При использовании лупы — приватный fullscreen экран "Только для [Имя]" → tap → результат → "Спрячь" → клик → результат скрыт → передай.

### 22. `Scene3D` интерфейс не покрывает выбор цели
**Найдено:** architecture
**Фикс:** Добавить `requestTargetSelection(eligibleIds: string[]): Promise<string>` для будущей RoundTableScene где клик по 3D-фигуре = выбор.
